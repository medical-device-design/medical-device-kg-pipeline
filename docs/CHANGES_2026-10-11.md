# Changes, 11 October 2026: data-quality fixes from the v0.0.5 query tests

v0.0.5 was tagged on 11 October. Before that, 109 test queries were run on a scratch copy of the graph (`Research/KG_QUERY_TEST_REPORT_2026-10-10.md`). They found 13 data-quality issues; none blocked the release. This change fixes the ones that come from our code. The others are FDA's own data and are now documented.

## 1. Fixed in the code

| # | Issue found | Fix |
|---|---|---|
| 1 | 7 UDI properties had no declaration in the published graph. `ontology/udi_extension.ttl` was never staged, only `ontology.ttl`. | The v0.0.6 staging uploads every ontology file. |
| 2 | The main record classes had no `rdfs:label`, so the okn.us browser and the MCP server showed bare IRIs. | Labels on recall ("Recall Z-1320-2026: Medline Industries, LP"), recall event, 510(k) ("K230972: Ingenia Elition…"), PMA and supplement ("P010001/S001: …"), HDE base, classification, establishment (its name), CLIA categorization ("WAIVED: HemoCue B-Glucose System - Glucose"), NAICS mapping, identity mapping and MAUDE report ("MAUDE 2249723-2019-01250 (Malfunction)"). |
| 3 | 48 junk product codes ("269", "N/A", "F T") were minted from MAUDE reporter text. | `common.product_code()` accepts only three-letter codes in every source. MAUDE keeps other text as `ex:reportedProductCodeText`, with no hub node. |
| 4 | 9,246 geocoded establishments had no name label. | Fixed by #2: the geocoded point is the establishment node, which now carries its name. |
| 5 | Shared nodes carried several labels. Regulation numbers had two ("880.5725" and "Infusion pump"), which doubled query rows. FirmName and ProductCode nodes also had variants. | Product codes take `rdfs:label` from classification only; other sources write `skos:altLabel`. Regulation numbers keep the 21 CFR title as label and the number as `skos:notation`. FirmName's label is the normalized name, with raw spellings as `skos:altLabel`. |
| 6 | MAUDE patient outcomes mixed one-letter codes (R, O, L, H, S, D, C, I, N) with words. | Codes are mapped to FDA's words in `event.py` and `tplc.py` (`common.outcome_label`). |
| 7 | 27,716 recalls held two address strings ("3 Lakes Dr" and "3 Lakes Dr, N/A"), and two copies of their text, one from each FDA feed. | Free text is whitespace-normalized and "N/A" address parts are dropped in both recall sources, so the two feeds produce one value. |
| 8 | 39 product codes were linked from recalls, HDE and Devices@FDA but had no hub node. | `recall_db.py` and `hde.py` write a typed hub stub for every code they link. |
| 9 | Recall initiation years 0010, 0012, 0013 and 1930 (FDA typos). | Values are kept as published, with `ex:dataQualityNote` saying the year is implausible. |

`scripts/patch_event_ttl.py` applies the `event.py` changes (#2, #3, #5 and #6) to the already-built `event.ttl`. It writes numbered 4 GB parts (`event_01.ttl` …), so the 26 million reports are not re-transformed, which would need about 75 GB of scratch space.

## 2. Confirmed as FDA's own data (not changed)

- **510(k) applicant "Y" (78 records), "Bd" (15) and "3M" (4).** These are the values in openFDA's file, e.g. K801873 and K854574, IVAC devices from the 1980s. "Bd" and "3M" are real firm names.
- **X-ray assembler installation dates in 2003: 21 reports, against about 16,000 a year from 2001 to 2005.** FDA's `assem.zip` has the same gap, so the dates are being read correctly.

## 3. Still open

- **Devices@FDA summary PDF links.** 4,971 have been verified so far. The HTTP check covers 5,000 documents a run at one request per second, so the remaining 230,000 need repeated runs, e.g. nightly.
- **Term pages.** `bmedesign.org/medical-device-kg/ns/…` IRIs do not resolve yet. This is website work.

## 4. Rebuild for v0.0.6

The changed layers were rebuilt from the cached downloads, with no new FDA download: classification, k510, pma, hde, recalls, recall_db, registrationlisting, clia, naics and tplc. `event.ttl` was patched into parts. The files go to lakeFS `develop`; merging into `main` starts the conversion and needs the PI's approval.
