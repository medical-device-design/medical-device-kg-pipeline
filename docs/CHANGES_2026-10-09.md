# Changes, 9 October 2026: three new sources, the vocabulary gate, and a live-graph inventory

This rebuild adds HDE, the full set of FDA consensus standards, and 21 CFR device regulations. It also declares every term the converters emit in the ontology. It continues `CHANGES_2026-10-02.md`.

Every module self-tests, and each new source was also checked against live FDA data (below). Nothing has been published yet. Sections 1–3 are laptop runs; section 3b is the first full build on VM .83.

## 2. New and changed files

| File | What it does |
|---|---|
| `pipeline/sources/hde.py` | **New.** HDE flat file (weekly). Supplements nest under the base HDE, as PMA does. The base node is backfilled when an HDE appears only through supplements. The build stops if the header changes. |
| `pipeline/sources/standards.py` | **New.** Bulk `standards.txt` plus the FDA detail page per standard. The detail page supplies the product codes, regulations, SDO and specialty group, which the flat file does not carry. Pages are fetched at 1 request per second and cached, so later runs only fetch new standards. Not ingested on purpose: standard texts (SDO copyright) and FDA staff contact details. |
| `pipeline/sources/cfr.py` | **New.** govinfo eCFR bulk XML for title 21, parts 800–898 and 1000–1050. Each section gets a heading, an **identification text** (the legal device definition), the **regulatory class** parsed from "(b) Classification", the text and the FR citation. Each RegulationNumber links to its section via `ex:hasCFRSection`. (The eCFR "full" API returned 406 for every Accept header.) |
| `pipeline/common.py` | `date_lit` now types MM/DD/YYYY dates, the format used by the CDRH flat files. |
| `pipeline/iri.py` | `hde(number, supplement)`. 31 minters are pinned. |
| `pipeline/sources/classification.py` | Emitted `ex:hasClassification`, which the ontology does not declare; it now emits the declared `ex:hasClassificationRecord`. |
| `pipeline/sources/pma.py` | `ex:aoStatement` → `ex:approvalOrderStatement`, shared with HDE. |
| `ontology/ontology.ttl` | **About 90 terms declared** that converters were already emitting but the ontology never declared (defect D2). Adds the HDE, standards and CFR vocabularies. Declared terms went from 163 to 254. |
| `ontology/shapes/premarket.shacl.ttl` | New shapes: HDE, RecognizedConsensusStandard, CFRTitle21Section. |
| `scripts/vocab_check.py` | **New gate:** every `ex:` term in the code must be declared. With `--out`, it also checks that every declared class is populated. Now passes with zero undeclared terms. |
| `scripts/live_check.py` | **New.** Runs fetch → transform → parse → SHACL (pyshacl) for any source, without publishing anything. |
| `licence_register.csv` | Rows added for hde, standards and cfr. |

### Three defects found only on real data, fixed on the branch

1. **Out of memory.** `json.loads` on a whole openFDA partition was killed on the 3.8 GB VM. Every openFDA source now streams one record at a time (`base.iter_openfda_results`, using ijson). Peak RAM for 510(k) went from 3.6 GB (killed) to 25 MB.
2. **Broken Turtle.** A country name with an embedded newline ("…\nCHILE") broke `recall_db.ttl`. `distribution_pairs` now uses `common.lit`, and a regression test was added.
3. **Oversized field.** `code_info` (lot and serial lists) is 411 MB of `recall_db.ttl`. A test build capped it at 4,000 characters, which affected 3,356 records.

   **PI decision (2026-10-09): no data loss.** The default is now `CODE_INFO_CAP = None`, so the full text is kept. `common.capped_pairs` remains available if hosting ever requires a cap, and when used it flags truncation explicitly.

   Cost of keeping the full text: `recall_db.ttl` is 584 MB raw and 127 MB gzipped. FRINK publishes HDT, which compresses repetitive serial lists well.

Also fixed: the `vocab_check` class-population check now streams the TTL. rdflib could not hold the 5.6 M-triple file.

Ontology corrections made while pushing: `ex:hasCFRSection` now has domain `ex:RegulationNumber` (it said `ex:ProductCode`, but `cfr.py` emits it on regulation nodes, so RDFS inference would have mis-typed every regulation as a product code). A duplicate declaration of `ex:centerClassificationDate` was removed.

## 3d. Every MAUDE report built on VM .83 (night of 2026-10-09)

The PI confirmed that okn.us can host billions of triples, so all reports were loaded, with no year or product-code limit.

`event.py` now carries the full structured record:

- **The device as reported:** brand, generic name, model, catalog, lot, UDI-DI and full UDI, manufacturer and country, operator, availability, evaluation by the manufacturer, and device age.
- **Report flags:** adverse event, product problem and summary report.
- **The report itself:** type of report, remedial action, reporter occupation and country, event location, the correction/removal number, and patient treatments.
- **Links:** `pma_pmn_number` links to the 510(k), PMA or HDE node.

Narratives are kept in full, but in their own file, `event_text.ttl`, so they can go open or licensed-only by moving one file.

Not ingested, on purpose:

- manufacturer contact persons (names, phone numbers);
- patient demographics (age, sex, weight, race, ethnicity).

| File | Reports | Triples | Turtle | Wall time | Peak RAM | riot | SHACL |
|---|---|---|---|---|---|---|---|
| event.ttl (structured) | 26,136,873 (16 skipped: unusable report ids) | **954,076,477** | 44.5 GB | 31 min (3 workers) | 103 MB | OK; riot counted 954,076,477, matching the converter | conforms, all 6 shape files, on a 116,218-report / 4.2 M-triple sample (2025 Q1 and 2005 Q1); hub warnings only |
| event_text.ttl (narratives) | 25,648,807 reports with narrative | **59,190,550** | 32.6 GB | (same run) | | OK, counted | n/a |

**What the reports carry:**

- 230,698 reports have event type Death.
- 13,209,790 carry a UDI-DI.
- Links:
  - 13,768,186 to 510(k)/De Novo nodes;
  - 5,682,296 to PMA nodes;
  - 23,364 to HDE nodes;
  - 26,125,495 to product codes.
- There are zero `medicaldevice.com` IRIs.

**MAUDE to UDI by device identifier.** Of 193,104 distinct UDI-DIs reported in MAUDE, 142,346 (73.7%) match an identifier in the UDI layer. This links an adverse-event report to the exact marketed device, its GMDN term and its labeler. The unmatched DIs have not been examined yet; likely causes are formatting variants (for example missing leading zeros) and devices no longer listed in GUDID. Checking and normalizing them is a follow-up.

**Totals for this rebuild (12 sources):** about 1.29 billion triples, including 59 M narrative triples, and about 93 GB of Turtle.
